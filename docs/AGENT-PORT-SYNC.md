# 让 Agent 帮你把「端口同步」接到其它用 HTTP 的语音插件

> 适用场景：某个插件能填一个「HTTP 语音接口」地址来合成语音（像 Aurabot 的「其他 HTTP 接口」），但它**不在**本插件内置自动同步的名单里。DSH 每次重启 web 端口会变，你不想每次都手动去改那个地址。
>
> 做法：把本文当作一段指令，整段发给 DSH 的 **agent 对话窗口**。agent 能读那个插件的源码、能跑命令，让它现场查明配置存在哪、怎么改能生效，然后按本插件给的「待填参数」写一份同步脚本/说明。因为每个插件的配置结构都不同，这一步只能由 agent 现场适配，插件本体做不到通用。

---

## 一、先告诉 agent 这几个关键事实（请原样保留）

- 这是 **DeepSeek Harness（DSH）**，插件都装在 `<profile>/node_modules/` 下，插件数据大多在 `~/.dsh/plugins-data/<插件名>/`。
- 本插件 **dsh-breeze-voice** 只做**本地语音**（Breeze TTS 2 本地引擎/桌面版），云端 TTS 不在范围。
- DSH 的 web 服务用**随机空闲端口**，每次重启都会变，环境变量 `DSH_WEB_URL`（例如 `http://127.0.0.1:2795`）指向当前端口。
- 本插件的语音合成接口是 `POST <当前web地址>/api/breeze-voice/preview`，请求体 `{"text":"要念的话"}`，返回标准 WAV（带 RIFF 头）。这个接口**不用认证**。
- **请求体故意不带 `voice`**：念的时候用本插件「本地语音」页当前选中的音色。这样换音色/调情绪/改连接方式都只改本插件设置页，目标插件那边不用动。
- 目标插件里要填的四项参数（从本插件设置页「接入其它本地语音插件」卡片复制，或调 `GET /api/breeze-voice/integrations` 拿 `httpGuide`）：
  - 接口地址：`<当前web地址>/api/breeze-voice/preview`
  - 请求方式：`POST`
  - 请求头：`Content-Type: application/json`
  - 请求体：`{"text":"{text}"}`（`{text}` 由目标插件替换成要念的话）

---

## 二、给 agent 的任务指令（复制这一整段发给 agent）

```
请帮我做一件事：让插件【目标插件名】里填的「Breeze 语音 HTTP 接口地址」，在 DSH 每次重启、web 端口变化后能自动同步，我不用手动改。

背景（务必先理解）：
- DSH web 端口每次重启随机变，当前地址见环境变量 DSH_WEB_URL。
- 我的本地语音插件 dsh-breeze-voice 的合成接口是 POST <web地址>/api/breeze-voice/preview，请求体 {"text":"要念的话"}，返回带 RIFF 头的 WAV，无需认证。
- 请求体里故意不带 voice，音色由 dsh-breeze-voice 设置页决定，所以同步时千万别给目标插件塞 voice 字段。

第一步：只做调查，先别改任何文件。请读目标插件源码（在 <profile>/node_modules/ 下）和数据目录（一般在 ~/.dsh/plugins-data/ 下），回答：
1. 它填的 HTTP 语音接口地址，具体存在哪个配置文件、哪个字段路径？把字段名和示例值贴出来。
2. 这个配置是「启动时读一次」还是「运行时会重载」？有没有官方的保存 API（类似 Aurabot 的 POST /aurabot/api/save）能在运行时改并立即生效？如果没有，改配置文件后需不需要重启 DSH 才生效？
3. 那个接口地址字段，能不能原地替换掉 URL 里的端口/主机部分，而不破坏路径、查询参数、以及 {text} 这类占位符？

第二步：根据调查结果决定怎么做，并说明理由：
- 如果它有运行时保存 API → 优先用那个 API 更新（内存+文件一起改，最稳）。
- 如果它只在启动时读配置 → 写一个「DSH 启动时执行一次」的同步脚本/改动，把当前 DSH_WEB_URL 的端口写进那个配置字段；并明确告诉我它要重启才生效。
- 无论哪种，只改「接口地址」这一个字段。目标插件的音色、情绪、人格、请求方式、请求头、请求体以及其它任何配置，一律不许改。
- 加护栏：仅当目标插件当前用的是 HTTP 语音引擎、且已填的接口地址指向 dsh-breeze-voice 的 /api/breeze-voice/preview 时才同步；否则一个字都别写。

第三步：验证。改完后请自测：
- 已接本插件 + 端口变了 → 只更新地址里的端口，其它字段逐一比对保持不变；
- 目标插件没用 HTTP 引擎 → 跳过、不写；
- 地址不指向本插件 → 跳过、不写。
把三种情况的结果贴给我。

注意：不要修改 dsh-breeze-voice 本身，也不要动任何插件的安装目录源码，只改目标插件的用户数据配置。改之前先备份那个配置文件。
```

---

## 三、agent 做完之后你要验收的三件事

1. **只改了地址端口**：目标插件的音色、情绪、人格设置跟之前一模一样，只是接口地址里的数字换了。
2. **护栏生效**：你把目标插件切回别的语音引擎、或把地址改成别的，重启一次，配置应该纹丝不动。
3. **重启生效**：DSH 重启后，目标插件念出来的声音还是本插件的（说明新端口接上了）；如果 agent 说需要重启才生效，就重启一次再验。

---

## 四、为什么 Aurabot 不用这么做

Aurabot 的配置机制已经被本插件内置适配了（`syncAurabotPort()`）：它有官方保存接口 `POST /aurabot/api/save`，配置字段是 `voice.http.urlTemplate`，所以本插件自己就能同步，你什么都不用干。本文是给**其它**插件用的——那些插件的配置格式本插件没有内置，只能请 agent 现场适配。

> 小提醒：如果哪天这个插件也成了常用款，你可以把 agent 当时的适配结论发回来，本鱼可以考虑把它也加进内置同步名单（那就又不用麻烦 agent 了）。

# 让 Agent 判断：「目标插件能不能用上本插件的本地语音」

> 适用场景：你装了本插件（dsh-breeze-voice），想让**另一个插件**也能用上本机的 Breeze 音色，但不确定那个插件到底能不能接、该怎么接。
>
> 做法：把本文当作一段指令，整段发给 DSH 的 **agent 对话窗口**。agent 能读那个插件的源码，让它按下面的决策树现场判断：有开放语音接口 → 给接法、把选择权交给你；没有但能填 HTTP → 给 HTTP 参数；两条都没有 → 明说放弃。
>
> **核心原则：agent 只负责「检测 + 出方案」，接不接、走哪条路，全部由你（用户）拍板。** 本插件不会探测到就自动接；它只把自己的开放服务摆在那儿，任何人（用户或插件作者）都可以主动来接，不设限制。

---

## 一、先告诉 agent 这几个关键事实（请原样保留）

- 这是 **DeepSeek Harness（DSH）**，插件都装在 `<profile>/node_modules/` 下，插件数据大多在 `~/.dsh/plugins-data/<插件名>/`。
- 本插件 **dsh-breeze-voice** 只做**本地语音输出端（TTS）**（Breeze TTS 2 本地引擎/桌面版），不碰语音输入识别，云端 TTS 不在范围。
- DSH 核心**没有统一的 TTS 服务注册机制**（只有语音输入 STT）。所以不存在「装个插件，所有插件语音下拉自动出现音色」这种事——这点和大模型 API 不一样。
- 本插件对外**开放了一个服务**，任何插件都能主动接（这是"摆在那儿等人接"，不是"本插件去接别人"）：

  ```js
  const bv = ctx.get('breezeVoice', true)        // 软取，没装也不报错
  bv.listVoices()                                // 同步：音色数组 [{id,name,description,ready,kind,refId?}]
  await bv.status()                              // 运行状态
  const { bytes } = await bv.speak(text, voiceId, { signal })  // 合成 → bytes 是 WAV Buffer
  bv.refreshRegistration()                       // 音色清单变了就刷新
  ```

- 本插件也提供 HTTP 合成接口 `POST <当前web地址>/api/breeze-voice/preview`，请求体 `{"text":"要念的话"}`，返回标准 WAV（带 RIFF 头），**不用认证**；请求体故意不带 `voice`，音色由本插件设置页决定。
- DSH 的 web 服务用**随机空闲端口**，每次重启都会变，环境变量 `DSH_WEB_URL` 指向当前端口。

---

## 二、给 agent 的任务指令（复制这一整段发给 agent）

```
请帮我判断插件【目标插件名】能不能用上我本机的 Breeze 语音音色，并按下面的决策树给我结论和接法。

最重要的前提：你只负责「检测 + 出方案」，接不接、走哪条路，全部由我（用户）拍板。
我没点头之前，不要写任何文件、不要改任何配置。

背景（务必先理解）：
- 这是 DeepSeek Harness（DSH），插件在 <profile>/node_modules/，数据在 ~/.dsh/plugins-data/。
- 我的本地语音插件 dsh-breeze-voice 开放了一个服务，任何插件都能主动接：
    const bv = ctx.get('breezeVoice', true)
    bv.listVoices()                                      // 同步返回音色数组 [{id,name,description,ready,kind,refId?}]
    await bv.status()                                    // 运行状态
    const {bytes} = await bv.speak(text, voiceId, {signal}) // 合成，bytes 是 WAV Buffer
    bv.refreshRegistration()                             // 刷新注册
- 它也有 HTTP 接口 POST <web地址>/api/breeze-voice/preview，请求体 {"text":"要念的话"}，返回带 RIFF 头的 WAV，无需认证；请求体故意不带 voice，音色由本插件设置页决定。
- DSH 核心没有统一的 TTS 注册机制，所以别指望"装了就自动出现在所有插件里"。
- 本插件不会去自动接别的插件（dsh-pet 是唯一已收录的例外）。它只把自己的开放服务摆在那儿，谁想接都行。

第一步：只做调查，先别改任何文件。请读目标插件源码和数据目录，回答：
1. 它有没有对外暴露、可供别的插件注册的语音服务接口？（类似 dsh-pet 的 ctx.provide('petApi7340', {voice:{register,...}}) —— 有 voice.register / 音色注册表 / registerVoiceProvider 之类）
2. 它有没有一个能让外部主动注册音色和合成函数的入口？（比如某个 Map/注册表，或某个 register 方法）
3. 它有没有内置的通用「其他 HTTP 接口」语音引擎（能填 地址 + 请求方式 + 请求头 + 请求体）？
4. 它有没有现成示例/文档展示过接第三方 TTS？把相关字段名和代码片段贴出来。

第二步：按下面的决策树，从上到下对号入座，给我结论：

【路径 1｜目标插件有开放的语音注册接口】
→ 告诉我"能接"，并给出**针对它实际 API** 的接法（不要只给模板）：
   - 用 ctx.get('breezeVoice', true) 拿服务，用 ctx.inject(['breezeVoice'], fn) 处理加载顺序；
   - 把 bv.listVoices() 转成它注册表要的格式，调它的 register；
   - synthesize 回调里写 (await bv.speak(text, voice, {signal})).bytes；
   - 说清音色 id 用裸 id、format 填 wav、timeoutMs 给足（本机合成可能几十秒）。
→ 然后把选择权交给我：问"要不要我现在按这个接？"，我点头你再动手，改之前先备份。

【路径 2｜没有开放注册接口，但有「其他 HTTP 接口」】
→ 告诉我"可以用 HTTP 接，不用等作者更新"，给这四项参数（接口地址里的端口用当前 DSH_WEB_URL）：
   - 接口地址：<当前 DSH 地址>/api/breeze-voice/preview
   - 请求方式：POST
   - 请求头：Content-Type: application/json
   - 请求体：{"text":"{text}"}   （{text} 由它替换成要念的话）
→ 强调三点：请求体故意不带 voice（音色由本插件设置页决定）；本插件不写它任何文件；DSH 重启后端口会变，要让它自动同步端口就另用一份"端口同步"说明。
→ 选择权交给我：要不要我帮你把参数填进它配置、或带你去它面板填？我点头再做。

【路径 3｜两条都没有】
→ 明说"这个插件目前没有对外的语音接口，也不能填 HTTP 地址，接不了"。
→ 不要硬改它源码、不要往它数据目录塞脚本（那会绕开它原来的音色/情绪设置、把它念成另一个味儿），也别动 DSH 核心。
→ 给一句建设性建议：可以把本插件的开放服务签名发给该插件作者，请对方加几行适配。本插件不限制任何用户或作者主动来接。

第三步：把结论贴给我，由我拍板走哪条路。我没同意前，一个字都别写。

全程护栏：
- 只碰"语音"相关的接口和配置，其它服务/配置一律不看不改。
- 接不接由我决定，你只负责检测 + 出方案。
- 不要反过来去改 dsh-breeze-voice 本身（它是"等人接"的一方）。
- 改任何配置前先备份；不修改任何插件的安装目录源码。
```

## 三、agent 做完之后你要验收的三件事

1. **结论对得上源码**：agent 说的"有/没有语音接口、字段名是什么"能在目标插件源码里找到对应代码，不是它凭空猜的。
2. **选择权在你手上**：agent 只是把方案和接法摆出来问你，没有在你没同意时就动手改文件。
3. **没碰不该碰的**：无论走哪条路，目标插件的音色/情绪/人格、DSH 核心、本插件本体都没被乱改；走路径 3 时它干脆什么都没写。

---

## 四、为什么不让本插件「探测到就自动接」

- **服务没有统一标准**：dsh-pet 的 `petApi7340.voice.register` 是它自己的私有服务，不是 DSH 核心标准；别的插件就算有语音服务，名字、形状也各不相同，且没有公开的服务枚举口——本插件没法可靠地"扫到就认"。
- **硬接会念串味**：像"往某个插件的 local 目录塞脚本"那种绕过对方设置的做法，会把人家原来的音色/情绪/人格全绕开，同一个人念出来变成另一个味儿——已弃用。
- **所以选择权交给你**：本插件只做两件事——把自己的开放服务 `breezeVoice`（和 HTTP `/preview`）摆在那儿，以及在设置页检测本机装了哪些本地语音插件、给出接入参数。**具体要不要接、怎么接，由你或 agent 现场判断决定。**

> - 已经用「其他 HTTP 接口」接上、想让端口随重启自动同步，见 [让 Agent 帮你同步端口](AGENT-PORT-SYNC.md)。
> - 如果 agent 检测后发现某插件其实有开放语音接口、并按路径 1 接好了，欢迎把它的服务名和接法发回来，本鱼可以考虑加进内置适配名单（那样就不用每次麻烦 agent 了）。
